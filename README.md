# Прогулки по Астане

Городской AI-помощник для Build with AI 2026, секция AI for Smart City. Цель — подобрать 1–3
места рядом с пользователем, объяснить выбор, показать время посещения, источник и честный статус
часов работы. Требования организаторов — [docs/case.md](docs/case.md).

## Текущее состояние

Реализованы чат, панель инструментов, темы оформления, контракт данных, передача округлённой
геолокации, четыре инструмента мест, серверные операции, сценарный mock и русский формат ответов.
Проверены режимы Responses и Chat Completions с замоканным SDK; запрос часов работает без данных мест.

**Реальные рекомендации подключены:** 1091 место из OSM/Wikidata и алгоритмы расстояний, часов,
лексического поиска, ранжирования и маршрута работают через `usecase/dependencies.ts`.
Проверены серверные mock-запросы с Экспо, Mega Silk Way, кофе и ночной активностью,
уточнения локации и мини-маршрут. В Chrome проверены карта, карточки, маршрут, обе темы и ширина 390 px.
Проверены шесть живых HTTP-запросов OpenAI Responses; подробности и ограничения —
[результаты проверки](docs/live-check-2026-10-19.json).
Добавлены карта OpenFreeMap, карточки, геолокация по кнопке и линия маршрута по прямой.
Текст, карточки и маркеры используют один серверный выбор рекомендаций.
Создан и закоммичен индекс **1091 × 256** векторов OpenAI `text-embedding-3-small`.
Семантический поиск работает с ключом OpenAI; без ключа и в `mock` — лексический поиск.

## Запуск

Нужны Node.js ≥22 и pnpm 10. Версия менеджера зафиксирована в `package.json`.

```bash
pnpm install
cp .env.example .env
pnpm check
pnpm dev
```

Для PowerShell вместо `cp`: `Copy-Item .env.example .env`. Откройте <http://localhost:3000>.
Файл примера включает `LLM_PROVIDER=mock`; ключ и база данных не нужны.

Что можно проверить сейчас:

1. «Который час?» → время Астаны; в панели появляется `get_current_time`.
2. «Еду с ребёнком — где рядом площадка?» → вопрос о локации, без выдуманных мест.
3. «Я сейчас возле Mega Silk Way, хочу прогуляться 30–60 минут» → определение места и
   поиск рядом; при текущем датасете и дневном времени находится NU Park.
4. «Я у Экспо, хочу что-то необычное на 1–2 часа» → уточнение здания.
   EXPO, квартал ЭКСПО-2017 и музей — разные объекты. «Я у Нур Алем, хочу посмотреть музей»
   определяет нынешний Alem.ai по подтверждённой истории того же объекта OSM.
5. «Построй маршрут на 2 часа» после сообщения с локацией → остановки из `plan_walk`,
   суммарное время учитывает переходы и посещения. Результаты зависят от времени и фильтров.

Производственная сборка и запуск:

```bash
pnpm build
pnpm start
```

Сборка использует `next/font/google`: ей нужен доступ к файлам Inter. Браузер получает шрифт
с самого приложения. Для сборки без ключа сохраните `LLM_PROVIDER=mock` в `.env`.
Если окружение блокирует служебный порт Turbopack, используйте `pnpm build --webpack`.

## Режимы модели

| `LLM_PROVIDER` | Поведение |
| --- | --- |
| `mock` | Сценарные ветки через настоящий диспетчер инструментов, без сети и ключа |
| `responses` | OpenAI Responses API; нужны `LLM_API_KEY` и доступная модель в `LLM_MODEL` |
| `chat` | Chat Completions; при необходимости укажите совместимый `LLM_BASE_URL` |

Настройки находятся в `.env.example`; настоящий ключ хранится только в `.env` и не коммитится.
Живая модель проверена на шести сценариях с реальным датасетом. Для тестов геолокации
использовались публичные точки у Mega и Байтерека, а не местоположение участника.
«Экспо» требует уточнения из-за нескольких разных объектов; Нур Алем определяется как
нынешний Alem.ai по подтверждённой истории OSM. Ночной фильтр испытан днём при текущем
серверном времени; это не подтверждает доступность мест в23:00.

## Инструменты и поиск

| Инструмент | Назначение |
| --- | --- |
| `get_current_time` | Время из контекста сервера |
| `resolve_location` | Название или алиас ориентира → координаты из датасета; неоднозначность не угадывается |
| `find_places` | Локация, предпочтения и фильтры → кандидаты с расстояниями и часами |
| `get_place` | Проверенные подробности объекта по OSM id |
| `plan_walk` | Маршрут с ограничением на ходьбу и время посещений |

Все аргументы проверяет Zod. Асинхронные вызовы ожидаются до отображения результата.
Рекомендации формируются из проверенных результатов инструментов; свободный финальный текст
модели не служит источником фактов. Сгенерированные предложения действий помечены.
Ночью рекомендуются только места с `open.status === 'open'`; неизвестные часы обозначаются явно.
Перед вылетом ассистент напоминает о времени дороги, регистрации и досмотра и не отдаёт весь
запас прогулке. Указанный бюджет ограничивает суммарное время ходьбы и посещения.

Запрос пользователя превращается в вектор и сравнивается с векторами мест по косинусному
сходству, затем применяются географические фильтры, часы и ранжирование. Лексика — резерв;
совпадения тегов учитываются отдельно. Базы векторов и отдельного сервиса нет: индекс —
статический JSON, поиск — в памяти сервера.

### Эмбеддинги (векторы мест)

Вектор — это 256 чисел, которыми модель OpenAI `text-embedding-3-small` описывает смысл текста
места: название, категория, теги, описание. Близкие по смыслу места и запросы получают близкие
векторы, поэтому «где выпить кофе» находит кофейни, даже если слова не совпадают.

Векторы всех мест лежат в `data/poi.vectors.json` и закоммичены: чтобы пользоваться ими,
ключ не нужен. Пересобрать файл нужно только после `pnpm collect`:

```bash
# в .env: LLM_API_KEY=<ключ OpenAI>, LLM_BASE_URL пустой
pnpm embed
```

Скрипт проверяет ответ и пишет файл атомарно; модель, размерность и SHA-256 `data/poi.json`
записаны в самом файле. После пересборки перезапустите сервер.

Чтобы превратить в вектор сам запрос пользователя, нужен ключ: семантический поиск работает
при `LLM_PROVIDER=responses`, заданном `LLM_API_KEY` и пустом `LLM_BASE_URL`. В остальных
случаях — `mock`, сторонний эндпоинт, нет ключа, устаревший индекс или ошибка API — используется
лексический поиск, и результат инструмента прямо об этом сообщает. Текст запроса и координаты
не сохраняются и не логируются.

## Подключение работы команды

В `src/server/places/usecase/dependencies.ts` уже подключены прямые импорты:

| Функции | Ожидаемый файл | Ответственный |
| --- | --- | --- |
| `readPlaces`, `getPlaceById` | `src/server/places/repo/places.ts` | Адиль |
| `readVectors` | `src/server/places/repo/vectors.ts` | Адиль |
| `lexicalScores` | `src/server/places/model/lexical.ts` | Абылай |
| `rankPlaces` | `src/server/places/model/rank.ts` | Абылай |
| `planWalk` | `src/server/places/model/route.ts` | Абылай |

Контракт — `src/server/places/model/places.schema.ts`. Поля с default в типах входных данных
описывают результат валидации; до валидации используйте `z.input<typeof ...Schema>`.
Алиасы ориентиров находятся в `usecase/landmarks.ts`; собственных координат они не содержат.
Дубли Mega Silk Way сопоставлены с проверенным OSM-зданием, для Байтерека выбирается монумент.
Историческое имя Нур Алем связано с точным OSM way/454857501 (нынешний Alem.ai) по истории
версий11–12. Музей, отдельный EXPO и квартал ЭКСПО-2017 не объединяются.
Ранжирование получает внутренний `query` и учитывает только подтверждённые совпадения тегов.
Абылай подключил фильтрацию бюджета до ограничения числа кандидатов. Публичная схема не менялась.
Если алгоритм выбирает одну остановку, она явно помечается как запасной вариант.

## Данные

Последний реальный сбор: **19 октября 2026, 15:19:33 по Астане (UTC+5)**,
или `2026-10-19T10:19:33.838Z`. Снимок OSM: `2026-10-19T10:18:05Z`.
Автоматически собрано **1091 POI**. Из 1101 исходного объекта удалено 9 дубликатов,
ещё один объект исключён по координатам. Это выборка именованных мест внутри bbox
51,03–51,25° с. ш., 71,25–71,65° в. д., а не полный реестр Астаны.

Категории без пересечений (сумма — 1091):

- **Еда и кафе: 591**.
- **Бары и ночные клубы: 92**.
- **Парки и сады: 38**.
- **Культура: музеи, галереи, театры и библиотеки: 28**.
- **Памятники и арт-объекты: 49**.
- **Достопримечательности и смотровые: 16**.
- **Развлечения: кино, площадки, тематические парки и зоопарки: 11**.
- **Торговые центры: 51**.
- **Спорт: 28**.
- **Религиозные объекты: 17**.
- **Прочие объекты и ориентиры: 170**.

Покрытие полей, доля от всех 1091 мест:

- **Часы работы `opening_hours`: 342 (31,35%)**.
- **Описание из OSM или Wikidata: 20 (1,83%)**,
  в том числе OSM — 3 (0,27%), Wikidata — 17 (1,56%).
- **Популярность из Wikidata: 24 (2,20%)**.
  Это нормализованное число sitelinks, а не рейтинг посетителей. Связь с Wikidata есть
  у 24 мест (2,20%). Ошибок пакетов обогащения: 0.

Проценты округлены до двух знаков. Наличие описания не означает подробный текст.
Наличие часов не подтверждает актуальность или статус «открыто сейчас».
Отдельной категории «архитектура» в контракте нет: объекты остаются в исходных категориях,
а не искусственно пересчитываются второй раз.

Сбор воспроизводится командой `pnpm collect` без ключей. Скрипт запрашивает Overpass,
нормализует и проверяет записи по общей Zod-схеме, удаляет одинаковые названия в радиусе 50 м,
запрашивает Wikidata пачками до 50 ID и создаёт `data/poi.json` и `data/collect_summary.json`.
Повторы и запасное зеркало предусмотрены. Названия на разных языках могут оставлять дубликаты.
Итоговый JSON вручную не редактируется. Проверка 20 записей и выявленные проблемы:
[data/quality-review.md](data/quality-review.md).

Источники: **© участники OpenStreetMap**, [ODbL](https://www.openstreetmap.org/copyright),
и **Wikidata**, [CC0](https://www.wikidata.org/wiki/Wikidata:Licensing).
Google Maps, 2GIS и Яндекс не используются.

`data/poi.vectors.json` создан командой `pnpm embed` **19 октября 2026** на всех 1091 POI.
Он содержит семантические представления исходных полей, а не новые описания мест.
Сбор POI не требует OpenAI.

## API и приватность

`POST /api/chat` принимает `{ messages: [{ role: 'user' | 'assistant', content: string }],
location?: { lat: number, lon: number } }` и возвращает `{ reply, toolCalls, recommendedPlaceIds }`.
Идентификаторы рекомендаций выбираются сервером по тем же правилам, что текст ответа;
карта и карточки дополнительно проверяют соответствующие результаты инструментов.

Координаты поля `location` проверяются и округляются до 3 знаков перед вызовом модели, в том
числе при прямом вызове агента. Интерфейс запрашивает геолокацию только по кнопке
и округляет её ещё в браузере. Отмена блокирует поздний ответ браузера; повтор запроса
использует текущее согласие. Модель не может подменить старт маршрута или точку
поиска произвольными координатами. Текст для определения локации сверяется с сообщениями пользователя.

Сессия живёт в памяти текущего запроса; аккаунтов и базы данных нет. Координаты и тексты запросов
не кэшируются и не логируются приложением. Ошибки провайдеров не возвращаются пользователю;
лог API содержит только категорию ошибки. Текст, который пользователь сам написал в сообщении,
не переписывается и в живом режиме передаётся выбранному провайдеру.

## Проверки и ограничения

`pnpm check` запускает типы, ESLint без предупреждений и юнит-тесты. Тесты проверяют контракт,
сценарный диспетчер, формат ответа, границы локации, бюджет маршрута и резервный поиск. SDK
в тестах замокан; их прохождение не подтверждает качество настоящего датасета или живой модели.

Фактические ответы и границы проверок находятся в [docs/scenarios.md](docs/scenarios.md).
Для повторного HTTP-прогона запустите приложение с `LLM_PROVIDER=mock`, затем `pnpm scenarios`:
скрипт сохраняет результаты в `docs/presentation-http-probes.json` и завершает работу с ошибкой
при нарушении ожиданий. Его локальные тестовые координаты не являются геолокацией участника.
Предыдущие проверки живой модели записаны отдельно в `docs/live-check-2026-10-19.json`;
они были сделаны до подключения векторов. План и зоны
ответственности — [docs/plan.md](docs/plan.md), требования сдачи — [docs/kickoff.md](docs/kickoff.md).

Проект рассчитан на один город. Полнота OSM не гарантируется. Данных о погоде, ценах, событиях,
загруженности и дороге до аэропорта нет. Маршруты приблизительны, по прямой с поправкой,
без пешеходного графа и учёта перекрытий.

## Сборка PDF из Markdown

```bash
python3 -m venv .venv-pdf
.venv-pdf/bin/python -m pip install -r scripts/pdf-requirements.txt
.venv-pdf/bin/python scripts/export_pdf.py
```

При активном окружении доступны `pnpm pdf` и `pnpm pdf:test`.
Pandoc разбирает фактические `docs/presentation.md` и `docs/scenarios.md`, ReportLab формирует
слайды и документ A4. Каждый заголовок первого уровня презентации начинает слайд; HTML-комментарии
служат заметками докладчика и не печатаются. Копии текста в Python нет.

Результаты — `output/pdf/presentation.pdf` и `output/pdf/scenarios.pdf`; совместимые копии для
сдачи — `docs/presentation.pdf` и `docs/scenarios.pdf`. Параметры `--output-dir` и
`--no-compat-copies` меняют расположение и отключают копии. Ошибка разбора, переполнение слайда
или неподдерживаемая конструкция останавливает экспорт с диагностикой.
Нужен локальный шрифт с кириллицей: Arial или DejaVu Sans. На Linux установите DejaVu Sans;
нестандартную папку задайте через `ASTANA_PDF_FONT_DIR`.

Проверки экспорта:

```bash
.venv-pdf/bin/python -m unittest discover -s scripts -p export_pdf_test.py
```

## Команда и сторонние компоненты

Саян — контракт, серверные операции, инструменты, интеграция и README; Абылай — алгоритмы;
Адиль — данные, сценарии и презентация; Саян также взял интерфейс.

**Предварительный шаблон раскрыт:** оболочка Next.js, цикл LLM-агента, реестр с инструментом
часов, чат с панелью активности, UI-компоненты и дизайн-система подготовлены до хакатона.
Предметная логика прогулок добавляется во время события и видна в истории коммитов.

Стек: Next.js, React, TypeScript, Tailwind CSS, Radix UI, Heroicons, Zod и OpenAI SDK.
Карта использует MapLibre GL и тайлы OpenFreeMap. Остальные пакеты и
версии перечислены в `package.json` и `pnpm-lock.yaml`.
Модели: OpenAI Responses API и эмбеддинги OpenAI `text-embedding-3-small` (256 измерений).
Экспорт документов: Pandoc (`pypandoc-binary`) и ReportLab,
версии в `scripts/pdf-requirements.txt`. Собственное обучение модели не выполняется.

Источники датасета: © участники OpenStreetMap,
[ODbL](https://www.openstreetmap.org/copyright), и Wikidata, CC0. На карте видна
атрибуция OSM, OpenMapTiles и OpenFreeMap. Данные Google Maps, 2GIS и Яндекса не используются. Собственная модель не обучается.
