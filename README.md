# Прогулки по Астане

AI-помощник для прогулок по городу. Проект сделан на Build with AI 2026, секция AI for Smart City,
кейс НИЦ Smart City ([docs/case.md](docs/case.md)). Пользователь пишет, где он и чего хочет, или
нажимает кнопку геолокации. Агент ищет по собственному датасету мест Астаны из OpenStreetMap и
Wikidata. В ответе 1–3 места: у каждого расстояние и минуты пешком, «почему», время на посещение,
что там делать, источник и честный статус часов работы. Места появляются на карте, а по запросу
агент строит мини-маршрут по пешеходным дорожкам OSM. Панель активности показывает, какие
инструменты вызвал агент и что они вернули.

Пример из кейса. Запрос «Я у здания Экспо 2017, хочу что-то необычное на 1–2 часа, пешком» в
режиме `mock` без ключа сейчас даёт такой результат. Ориентир определяется как «Alem.ai (бывший Нур
Алем), территория ЭКСПО», а сам старт в выдачу не попадает. Ответ: «25-ти летие Независимости»,
507 м, 9 мин; «Аллея мира и согласия», 539 м, 10 мин; NU Park, 1173 м, 21 мин. Для каждого места
сказано «часы работы неизвестны — уточните перед выходом», дана ссылка на объект в OSM, а идея
«что делать» помечена как сгенерированная. Если рядом мало музеев, ответ говорит это прямо. Выдача
зависит от времени запроса, потому что часы работы проверяются на текущий момент.

## Быстрый старт

Нужны Node.js 22 или новее и pnpm 10 (точная версия указана в `package.json`).

```bash
git clone <ссылка на репозиторий> astana-walks
cd astana-walks
pnpm install
cp .env.example .env        # PowerShell: Copy-Item .env.example .env
pnpm dev
```

Откройте <http://localhost:3000>. Скопированный `.env` включает `LLM_PROVIDER=mock`, поэтому
**ключ не нужен**. Сценарии идут через настоящие инструменты, датасет и алгоритмы. Модели нет,
поиск лексический. **Копировать `.env.example` обязательно:** без `.env` сервер по умолчанию
включает режим `responses` и требует ключ.

Живая модель: впишите в `.env`

```bash
LLM_PROVIDER=responses
LLM_MODEL=gpt-6-luna
LLM_API_KEY=<ключ OpenAI>
```

С ключом модель сама выбирает инструменты и аргументы, а запрос кодируется эмбеддингом для
семантического поиска.

Производственная сборка:

```bash
pnpm check     # типы, ESLint без предупреждений, юнит-тесты → GATE GREEN
pnpm build
pnpm start     # порт можно задать: pnpm start -p 3211
```

`pnpm build` берёт шрифт Inter через `next/font/google`, поэтому сборке нужен интернет. Браузер
потом получает шрифт с самого приложения. Если среда блокирует служебный порт Turbopack, соберите
через `pnpm build --webpack`. Отдельный standalone-пакет: `pnpm prepare:standalone` после сборки,
затем `node .next/standalone/server.js`. Скрипт копирует статику и удаляет из пакета файлы `.env*`,
поэтому переменные окружения задаются процессу при запуске.

## Переменные окружения

Все переменные перечислены в `.env.example`. Настоящий ключ хранится только в `.env`, а `.env` не
коммитится.

| Переменная | В примере | Назначение |
| --- | --- | --- |
| `LLM_PROVIDER` | `mock` | `mock` — сценарный агент без сети и ключа; `responses` — OpenAI Responses API; `chat` — Chat Completions (OpenAI или совместимый эндпоинт). Без значения — `responses` |
| `LLM_MODEL` | `gpt-6-luna` | Модель агента |
| `LLM_API_KEY` | пусто | Ключ OpenAI. Нужен для `responses`/`chat` и для `pnpm embed` |
| `LLM_BASE_URL` | пусто | Сторонний OpenAI-совместимый эндпоинт, только с `chat`. Если задан, эмбеддинги запроса не отправляются и поиск лексический |
| `OPENAI_VECTOR_STORE_ID` | пусто | Возможность шаблона (`file_search`). В продукте не используется |
| `OPENAI_WEB_SEARCH` | `false` | Возможность шаблона (веб-поиск). В продукте выключена |
| `NODE_ENV`, `PORT` | `development`, `3000` | Стандартные переменные Node.js/Next.js |

## Архитектура

Это одно приложение Next.js (App Router) без отдельного бэкенда и без базы данных. Интерфейс
построен по Feature-Sliced Design (`src/views`, `src/widgets`, `src/entities`, `src/shared`).
Сервер разбит на ярусы `src/server/{kernel, agent, places}` в порядке
`model → repo → usecase`. Подробности — в [docs/architecture.md](docs/architecture.md).

```
браузер ── POST /api/chat {messages, location?} ──▶ проверка Zod, округление координат до ~100 м
                                                    │
                                   цикл агента (responses | chat | mock), до 10 шагов
                                                    │
     resolve_location ─ find_places ─ get_place ─ plan_walk ─ get_current_time   (TOOLS)
                                                    │
     data/poi.json · data/poi.vectors.json · data/walking-graph.json  +  чистые алгоритмы
     (расстояния, часы OSM, лексика, ранжирование, маршрут, A* по пешеходному графу)
                                                    │
     ответ собирает код из проверенных результатов инструментов:
     { reply, toolCalls, recommendedPlaceIds, recommendations }
                                                    │
     чат с карточками мест и панелью активности · карта MapLibre + OpenFreeMap
```

| Инструмент | Что делает |
| --- | --- |
| `resolve_location` | Находит в датасете ориентир, названный пользователем («у Экспо», «возле Mega»). Неоднозначный ориентир не угадывается, а уточняется |
| `find_places` | Ищет кандидатов по запросу, локации, радиусу, категориям и доступности. Возвращает расстояния, минуты и статус часов |
| `get_place` | Возвращает проверенные данные места по OSM id |
| `plan_walk` | Строит маршрут из 1–3 остановок в пределах общего бюджета (ходьба плюс посещения) |
| `get_current_time` | Время из контекста сервера (инструмент шаблона) |

Аргументы каждого инструмента проверяет Zod, потому что это свободный текст модели. Модель только
выбирает инструменты и аргументы. **Финальный ответ формирует код** (`formatReply.ts`) из
проверенных результатов инструментов. Поэтому в ответе нет мест, расстояний и часов, которых не
вернул инструмент. Тот же код отдаёт структурированные `recommendations` для карточек, так что
текст и карточки совпадают. Маркеры и линия маршрута на карте тоже берутся только из результатов
инструментов. Браузер датасет не читает.

## Как работает RAG

1. **Сбор.** `pnpm collect` запрашивает Overpass API по bbox Астаны, нормализует объекты, проверяет
   их Zod-схемой и удаляет дубликаты. Затем добавляет описания и популярность из Wikidata и
   свободные фото из Wikimedia Commons. Результат — `data/poi.json`.
2. **Индекс.** `pnpm embed` превращает текст каждого места (название, категория, теги, описание)
   в вектор OpenAI `text-embedding-3-small` на 256 измерений и пишет `data/poi.vectors.json`. Файл
   закоммичен и содержит SHA-256 датасета, поэтому устаревший индекс не используется.
3. **Поиск.** В режиме `responses` запрос кодируется той же моделью, и в памяти сервера считается
   косинусное сходство со всеми местами. Векторной базы нет. Без ключа, в `mock`, со сторонним
   эндпоинтом или при ошибке API работает лексический поиск (нормализация и словарь синонимов),
   и ответ прямо об этом говорит.
4. **Ранжирование.** Сначала места фильтруются по радиусу ходьбы, категориям и доступности. Затем
   считается оценка `0,40·смысл + 0,25·близость + 0,15·часы + 0,10·популярность + 0,10·теги`.
   Закрытые места опускаются вниз, ночью рекомендуются только места со статусом «открыто».
5. **Маршрут.** `plan_walk` подбирает 1–3 остановки и меряет переходы алгоритмом A* по графу
   пешеходных дорожек OSM. Граф хранится локально, поэтому координаты не уходят внешнему
   маршрутизатору. Прямых линий через здания на карте нет.
6. **Ответ с источниками.** У каждого места указаны ссылка на объект в OpenStreetMap и источник
   описания (OSM или Wikidata). Всё, чего нет в данных («что делать»), помечено как
   «сгенерированная идея». «Открыто» говорится только по разобранным часам OSM.

## Данные

Последний сбор прошёл 19 октября 2026 (`collectedAt` `2026-10-19T13:22:24Z`, снимок OSM
`2026-10-19T13:20:21Z`). Цифры взяты из [data/collect_summary.json](data/collect_summary.json).

- **1250 мест** в bbox 51,03–51,25° с. ш., 71,25–71,65° в. д. Из 1445 исходных элементов OSM
  удалено 62 дубликата. Исключены гостиницы и посуточное жильё (131 объект) и одна частная
  площадка.
- По категориям: кафе 306, рестораны 168, фастфуд 118, бары 89, ночные клубы 3, детские площадки
  283, парки 34, сады 3, памятники 36, достопримечательности 17, арт-объекты 13, торговые центры
  51, театры 15, кино 9, музеи 9, библиотеки 8, галереи 2, спорт 28, религиозные объекты 17,
  смотровые 1, тематический парк 1, прочее 39.
- **Часы работы** (`opening_hours`) есть у 323 мест (25,84%). **Описания** есть у 47 (3,76%):
  44 из Wikidata и 3 из OSM. Связь с Wikidata подтверждена у 23 мест. **Фото** из Wikimedia
  Commons есть у 15 мест (1,2%), только под свободными лицензиями.
- 283 безымянные детские площадки названы по шаблону «Детская площадка, <ближайшая улица OSM>».

Это выборка именованных объектов, а не полный реестр города. Наличие часов не подтверждает, что
они актуальны. Проверка 20 случайных записей — в [data/quality-review.md](data/quality-review.md).

**Пешеходный граф** `data/walking-graph.json` собран из OSM 19 октября 2026: 134 017 узлов,
309 938 направленных рёбер, 32 726 линий, 862 компоненты связности. Правила отбора и SHA-256
записаны в [data/walking-summary.json](data/walking-summary.json). Закрытый и частный доступ,
ворота и броды исключены. Ступени допускаются, поэтому доступность маршрута для коляски не
гарантируется.

Пересборка данных. `data/*.json` вручную не редактируются.

```bash
pnpm collect                                                   # места, ключ не нужен
pnpm tsx --conditions=react-server scripts/collectWalking.ts   # пешеходный граф, ключ не нужен
pnpm embed                                                     # векторы; нужен LLM_API_KEY, LLM_BASE_URL пустой
```

После `pnpm collect` нужно снова выполнить `pnpm embed`, потому что индекс привязан к SHA-256
датасета. Затем перезапустите сервер.

## Сценарии

Шесть сценариев кейса, фактические ответы системы и ограничения описаны в
[docs/scenarios.md](docs/scenarios.md). В пустом чате те же сценарии показаны карточками.
Повторить HTTP-прогон:

```bash
pnpm dev                                  # в отдельном терминале, LLM_PROVIDER=mock
pnpm scenarios                            # или: pnpm scenarios http://127.0.0.1:3211
```

Скрипт отправляет десять запросов в `/api/chat`: шесть сценариев кейса и проверки на Нур Алем,
коляску, маршрут и отсутствие локации. Результаты записываются в
`docs/presentation-http-probes.json`. Если нарушен контракт ответа, скрипт завершается с ошибкой:
например, места без источника, «открыто» без данных, маршрут сверх бюджета или пустая
рекомендация. Координаты в скрипте — публичные тестовые точки.

## Приватность и этика

- Геолокация запрашивается только по кнопке. Координаты округляются до 3 знаков (~100 м) в
  браузере и повторно на сервере. Их можно отозвать, и тогда они удаляются из истории запросов.
- Аккаунтов и базы данных нет. Координаты и тексты запросов приложение не сохраняет и не
  логирует. Ошибки провайдера в браузер не попадают, а в лог пишется только категория ошибки.
- В режиме `mock` сервер ничего не отправляет в сеть. Браузер загружает только тайлы карты и фото
  Commons, и координаты пользователя в эти запросы не попадают. В живом режиме текст сообщения и
  округлённая точка передаются OpenAI.
- Факты берутся только из открытых данных с указанием источника. Сгенерированное помечено.
  «Открыто» без данных не говорится. Неизвестные удобства (розетки, тишина) называются
  неизвестными и не выводятся из категории.
- Данные Google Maps, 2GIS и Яндекса не собираются.

## Ограничения

- Город один, OSM неполон. У трёх четвертей мест нет часов работы, у большинства нет описаний.
- Нет данных о погоде, ценах, событиях, загруженности и дороге до аэропорта. Перед вылетом
  ассистент оставляет запас времени, но не знает реального времени регистрации.
- Время на посещение оценивается по категории. Часы проверяются на момент запроса, а не на всё
  время прогулки.
- Без ключа поиск только лексический и хуже понимает перефразированные запросы.
- Пешеходный граф не подтверждает подход ко входу, временные перекрытия и доступность для
  коляски.
- Модель не обучалась. Живая модель влияет на выбор инструментов, но не на факты в ответе.

## Проверки

```bash
pnpm check          # typecheck + ESLint --max-warnings 0 + юнит-тесты, параллельно
```

Последний прогон: 44 файла, **565 тестов** пройдено, GATE GREEN. Тесты проверяют контракт,
алгоритмы часов, ранжирования и маршрута, A*, формат ответа, границы локации и приватности,
резервный поиск и диспетчер `mock` на настоящем датасете. SDK OpenAI в тестах замокан, поэтому
тесты не подтверждают качество живой модели. Для этого есть `pnpm scenarios` и исторические живые
прогоны [docs/live-check-2026-10-19.json](docs/live-check-2026-10-19.json) и
[docs/live-semantic-check-2026-10-19.json](docs/live-semantic-check-2026-10-19.json). Оба прогона
сделаны на более ранней версии: 1091 место, лексический поиск и временная локальная модель
эмбеддингов, которую потом заменили на OpenAI. Сейчас они служат только историческим
свидетельством.

## Раскрытие: шаблон и сторонние компоненты

**Предварительный шаблон.** Проект начат с заготовки, подготовленной до хакатона (коммит
`095f007`). В ней были: оболочка Next.js + TypeScript, цикл LLM-агента с адаптерами Responses и Chat
Completions и режимом `mock`, реестр инструментов с одним инструментом `get_current_time`, чат с
панелью активности, библиотека UI-компонентов на Radix, дизайн-система, ESLint/Vitest-гейт
`pnpm check` и слой PostgreSQL/Prisma/Docker (удалён в начале события). Предметной логики в
шаблоне не было. Датасет, сбор, инструменты мест, алгоритмы, поиск, маршрут, карта и экран
написаны во время хакатона, что видно в истории коммитов.

| Компонент | Как используется | Лицензия / условия |
| --- | --- | --- |
| OpenStreetMap (Overpass API) | Места, часы, теги, пешеходный граф | ODbL, «© участники OpenStreetMap» |
| Wikidata | Описания, популярность (sitelinks), ссылки на фото | CC0 |
| Wikimedia Commons | Фото мест; автор и лицензия показаны на каждой карточке | CC0 / CC BY / CC BY-SA / PD, по файлу |
| OpenAI `gpt-6-luna` (Responses API) | Выбор инструментов в живом режиме | Условия OpenAI API |
| OpenAI `text-embedding-3-small` | Векторы мест и запроса, 256 измерений | Условия OpenAI API |
| MapLibre GL JS | Карта в браузере | BSD-3-Clause |
| OpenFreeMap, OpenMapTiles | Векторные тайлы и стиль карты; атрибуция видна на карте | Условия OpenFreeMap; OpenMapTiles, данные © OSM |

| Radix UI, Heroicons, Tailwind CSS | Интерфейс | MIT |

исходящие ссылки «Открыть в…» на карточке места: ссылка открывает поиск по названию и координатам
из OSM. Данные из этих сервисов не берутся.
