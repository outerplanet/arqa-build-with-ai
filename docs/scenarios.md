# Тестовые сценарии и ограничения

Документ сдаётся отдельно (экспорт в PDF). Каждый сценарий — вход, что ожидаем по требованиям кейса
и **фактический ответ системы**. Фактические ответы вписываются после прогона на реальных данных
(владелец — Адиль, с 18:00).

Проверка каждого ответа:

- [ ] 1–3 конкретных места рядом, с расстоянием и минутами пешком;
- [ ] у каждого — «почему», время на посещение и «что делать там»;
- [ ] источник помечен: OSM / Wikidata / сгенерированная идея;
- [ ] нет уверенного «открыто сейчас» без данных о часах работы;
- [ ] ясно, какая локация и какие фильтры использованы.

## 1. Экспо, необычное на 1–2 часа (пример из кейса)

- **Вход:** «Я у здания Экспо 2017, хочу что-то необычное на 1–2 часа, пешком.»
- **Ожидаем:** локация определена по тексту («Экспо» → Нур Алем); 2–3 места в пешей доступности;
  предложение мини-маршрута, который укладывается в 1–2 часа.
- **Фактический ответ:** *(вписать после прогона)*

## 2. Mega Silk Way, прогулка 30–60 минут

- **Вход:** «Я сейчас возле Mega Silk Way, хочу прогуляться 30–60 минут — что посоветуете?»
- **Ожидаем:** места на открытом воздухе и рядом (парки, набережная, смотровые, арт-объекты); время
  на посещение вместе с дорогой — в пределах часа.
- **Фактический ответ:** *(вписать)*

## 3. Тихое место с кофе и розеткой

- **Вход:** «Хочу тихое место с кофе и розеткой недалеко от меня.» (геолокация из браузера)
- **Ожидаем:** кафе и библиотеки; розетки и Wi-Fi — только если есть в данных OSM, иначе честно
  «про розетки данных нет»; статус часов работы.

- **Ожидаем:** площадки, зоопарк, детские и интерактивные музеи; если локации нет — вопрос «где вы
  находитесь?».

## 5. Турист, 2 часа перед вылетом

- **Вход:** «Я — турист, у меня 2 часа перед вылетом: что можно посмотреть поблизости?»
- **Ожидаем:** уточнение, где пользователь сейчас; запас времени на дорогу в аэропорт; 1–2
  главные достопримечательности, а не длинный список.
- **Фактический ответ:** *(вписать)*

## 6. Необычная ночная активность

- **Вход:** «Ищу необычную ночную активность на последние пару часов.»
- **Ожидаем:** только места, открытые сейчас по данным OSM; если часов работы нет — это сказано

## Как система обрабатывает сомнительные и неполные данные

- **Часы работы.** Разбираются из OSM `opening_hours`. Не разобрано или нет данных — статус
  «неизвестно», и ответ прямо говорит «уточните перед выходом». Праздничные дни не учитываются —
  уверенность понижается.
- **Описания.** Из OSM или Wikidata. Сгенерированные моделью помечены как сгенерированные.
- **Закрытые места и временные мероприятия.** OSM может отставать от реальности: в ответе есть
  ссылка на объект в OSM, где можно проверить и исправить данные. Событий (выставок, концертов) в
  данных нет — система их не выдумывает.
- **Расстояния.** По прямой с поправкой ×1,3 на изгибы улиц, а не по реальному пешеходному графу.

## Этика и приватность

- Координаты пользователя округляются до ~100 м ещё в браузере; сервер их не хранит и не логирует.
  Базы данных нет.
- Геолокация — только по явному нажатию, с пояснением, что передаётся.
- Пользователь всегда видит, какие данные использованы: локация и откуда она, фильтры, источник
  каждого места; в панели активности — все вызовы инструментов.
- Модель не утверждает того, чего нет в данных; всё сгенерированное помечено.

## Ограничения

- Полнота OSM по Астане неравномерна: часть кафе без часов работы, у многих мест нет описания.
- Нет данных о загруженности, ценах, погоде и событиях.
- Маршрут — по прямой, без учёта переходов и перекрытий.
- Один город; данные обновляются перезапуском `pnpm collect`, а не в реальном времени.
